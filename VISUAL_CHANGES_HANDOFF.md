# УРМ 2.2.3 — точные визуальные правки второго прохода (19.10.2026)

## Базовая версия

Исходный **именно для этого прохода** проект: `urm-platform-2.2.3-visual.zip` (предыдущий архив с правками подсказок `?`, синей/зелёной линий, компактных панелей и пр.). Новый результат: `urm-platform-2.2.3-compact.zip`.

Не путать с чистым `urm-platform-2.2.3.zip`: в нём **нет** правок первого визуального прохода. Чтобы получить итоговое оформление из чистого ZIP, нужно применить сначала правки первого прохода, затем второго, либо сразу взять полный итоговый `urm-platform-2.2.3-compact.zip`.

## Цель

На страницах 01–09 показывать больше визуализаций без лишней вертикальной прокрутки. Не уменьшать KPI-карточки, не убирать таблицы, не изменять формулы, SQL, бизнес-логику, авторизацию, права и снимки данных. Удалить дублирующие локальные элементы, если верхний фильтр уже однозначно задаёт объект. Сохранить пояснения об аналитическом характере расчётной дельты.

## Какие файлы изменены относительно `-visual.zip`

1. **`app.py`** — функция `top_bar`, функция `run`.
   - Шапка теперь создаёт колонки с `vertical_alignment="center"`, чтобы блок учётной записи и сведения о снимке стояли на общей вертикали с заголовком.
   - Контейнер `top = st.container(key="urmtop")` позволяет задать стили только шапке, не затрагивая другие сетки.
   - Глобальные фильтры (`filter_bar`), расчёт среза и роутинг данных НЕ менялись.

2. **`urm/style.py`** — только CSS и JS интерфейса.
   - `.block-container`: верхнее поле `0.75rem → 0.45rem`, нижнее `1.25rem → 1rem`.
   - `stMainBlockContainer`: уменьшен вертикальный gap основного содержимого; внутри `urmfilters`/`urmpanel` тоже уменьшены внутренние отступы.
   - Контейнер аккаунта (`st-key-urmaccount`): вертикальное выравнивание по центру, минимальная высота `91px`; внутренние отступы и зазоры уменьшены. Для шапки используется ключ `urmtop`.
   - `st-key-urmfilters`: padding уменьшен с `10px 14px 11px` до `7px 12px 8px`, прежний отступ сверху 8px → 2px.
   - `st-key-urmpanel`: padding `12px 15px 11px → 9px 12px 8px`, меньше расстояние после названия графика.
   - `.urm .notice`: жёлтая плашка **не удалена**; padding `8px 12px → 6px 10px`, margin `6px 0 8px → 0 0 3px`.
   - `.urm .section-head` / `.section-sub`: меньше внешние отступы.
   - Старые CSS-классы `.urm-material-summary` и др. удалены, так как сам повторяющийся блок на странице 05 убран. Добавлена `.urm-customer-summary` для компактных реквизитов на странице 04.
   - `#urm-option-tooltip`: `z-index:2147483647 !important`, позиционирование `fixed`, родитель `document.body`.
   - В `DRAG_JS` popup для полного названия пункта списка позиционируется **рядом со списком**, по доступному свободному пространству слева/справа. Ранее он размещался по координатам курсора и выглядел как всплывающий **под** списком. После задержки 300 мс слой дополнительно перемещается в конец `document.body` для предотвращения перекрытия. При скролле/нажатии/Escape окно исчезает. Без новых зависимостей.
   - Существующее перетаскивание таблиц мышью сохранено.

3. **`views/report.py`** — только компоновка, подписи и скрытие лишних локальных виджетов.
   - `labs_page` (02): график «Риск по месяцам» уменьшен с 440 до 385px, нижний отступ Plotly установлен 105px для легенды. Тепловая карта оставлена самостоятельной широкой секцией для читаемости длинных названий лабораторий.
   - `customers_page` (03): удалён `cust_pick` («Найти заказчика») и кнопка «Открыть карточку», поскольку глобальный фильтр «Заказчик (БИН)» уже фильтрует страницу. **Переход на 04 работает через меню.** Единственный локальный текстовый поиск оставлен только для таблицы «Реестр заказчиков» и перенесён **под графики непосредственно перед таблицей**. Подпись «Поиск только в реестре», она не затрагивает KPI и визуализации. Убран фильтр таблицы по `cust_pick`; фильтрация по БИН/названию через `cust_search` сохранена. Пончики и Топ-100 не удалены.

   - `customer_card` (04): если текущий срез содержит только **одну пару лаборатория+БИН**, второй селектор `card_pick` не показывается; иначе сохраняется. Реквизиты «Заказчик/БИН/Лаборатория/Статус/Риск/Последний месяц» вместо высокой сетки `info_strip` идут компактной строкой; все поля сохраняются и экранируются через `html.escape`. Выбор `_card_target` из прежней навигации остаётся совместимым.
   - `materials_page` (05): если в текущем срезе только один материал, второй селектор `mat_pick` не показывается, материал определяется автоматически. Если доступно несколько — селектор **остаётся**, так как выбирает объект только для детальных графиков; глобальный фильтр задаёт срез KPI и всех таблиц. Текст селектора «Материал на графиках ниже». `short_label(..., 70)` удалён: полное имя в списке. Удалена повторная полоска «Выбранный материал / По умолчанию — ...»; код выбранного материала добавлен в заголовок графика `Динамика материала <код>`, полное имя — в подсказку `?` рядом с графиком. Для двух первых KPI подпись «в текущем срезе» вместо «по всем материалам», чтобы не противоречить верхнему фильтру.
   - Таблицы и Excel, состав KPI, математические выражения для рисков/дельт, условия выбора **не менялись**.

## Что НЕ трогали

`urm/report_core.py` (исходный генератор), `urm/tables.py`, `urm/notices.py` (подсказки `?` первого прохода сохранены), `urm/engine.py`, SQL, `urm/snapshot.py`, авторизацию, пользователей, роли, фильтры в `app.filter_bar`, конфигурацию базы, тесты и зависимости.

## Что важно в поведении

- Общий фильтр **«Заказчик (БИН)»** меняет срез всех страниц. На странице 03 нет кнопки перехода — пользователь открывает страницу 04 в меню. Если в срезе один заказчик в одной лаборатории, карточка открывается сразу без второго выбора. Если несколько лабораторий для одного БИН или нет выбранного БИН — селектор на 04 остаётся для выбора конкретной пары.
- Общий фильтр **«Материал»** меняет весь срез. На 05 при нескольких материалах остаётся локальный выбор для **детальных** графиков. Это не дублирующий глобальный фильтр по смыслу.
- Popup с полным именем в dropdown реализован через внедрённый JS и структуру DOM Streamlit (`role=option`, `data-baseweb`). Из-за возможных изменений Streamlit/браузера проверить в реальном браузере. Если меню занимает почти весь экран, popup может частично накладываться на него — слой всегда выше списка.
- Таблицы намеренно оставлены друг за другом; не скрываются и не урезаются.

## Установка

**Вариант А, безопаснее:** распаковать полный `urm-platform-2.2.3-compact.zip` в отдельную папку, перенести туда существующую **свою** `.env`/конфигурацию (НЕ выкладывать её в чат), использовать имеющиеся данные, запустить `run_demo.bat` / `run_demo.ps1` или `docker compose up -d --build`. Не затирать рабочие снимки/секреты.

**Вариант Б, минимальная замена файлов в рабочей версии `-visual.zip`:** после резервной копии заменить `app.py`, `views/report.py`, `urm/style.py`, `urm/charts.py`. По желанию скопировать `CHANGELOG.md` и `VISUAL_CHANGES_HANDOFF.md`. Остальные файлы не менять. Если рабочая версия была **чистая** `urm-platform-2.2.3.zip`, лучше использовать полный новый архив, потому что там содержатся правки предыдущего прохода.

При локальном запуске перезапустить приложение (в проекте отключено слежение за файлами: `fileWatcherType=none`) и выполнить Ctrl+F5 в браузере.

## Проверка и ограничение

- Успешны Python AST/compileall для затронутых модулей и проверка синтаксиса JS (`node --check`).
- Исходный `urm/report_core.py` из `-visual.zip` совпадает побайтно.
- Полный Streamlit-рендер и `pytest tests/test_rules.py` в текущей среде **не выполнены**: отсутствуют `streamlit`, `psycopg`, `duckdb`, `pyarrow`; `pytest` останавливается при `ModuleNotFoundError: psycopg`. `ruff` также недоступен. Не утверждать, что визуальное поведение на Windows уже проверено.
- Ручная проверка: (1) шапка 01/02/03/04/05, (2) предупреждение и расстояние до KPI, (3) длинные пункты dropdown, (4) глобальный выбор одного/нескольких БИН, (5) одиночный/множественный материал 05, (6) сохранение графиков и Excel, (7) читаемость тепловой карты на 1280 и 1920px.
