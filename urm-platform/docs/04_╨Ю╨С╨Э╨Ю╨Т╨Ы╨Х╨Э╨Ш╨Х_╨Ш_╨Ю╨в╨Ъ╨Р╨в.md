# 04. Обновление и откат

Каждая версия платформы — это три вещи с одним номером:

1. **тег в git** `v2.1.0` — код;
2. **образ Docker** `urm-platform:2.1.0` — собранная программа;
3. **версия базы** платформы — номер последней применённой миграции (`tools/migrate.py status`).

Номер текущей версии записан в файле `VERSION`, виден в боковой панели интерфейса и в `.env` (`URM_VERSION`).

## Обновление до новой версии

```bash
cd urm
git fetch --tags
git checkout v2.2.0                    # нужная версия
# в .env поменять URM_VERSION=2.2.0
docker compose run --rm -e URM_ADMIN_USER=<адм.> -e URM_ADMIN_PASSWORD='<пароль>' urm python tools/migrate.py up   # если в CHANGELOG указаны изменения базы
docker compose up -d --build
docker compose exec urm python tools/doctor.py
```

Старый образ `urm-platform:2.1.0` остаётся на сервере. Пока его не удалили, откат занимает секунды.

## Откат на шаг назад

**Только программа** (база не менялась):

```bash
git checkout v2.1.0
# в .env: URM_VERSION=2.1.0
docker compose up -d          # образ 2.1.0 уже есть — пересборка не нужна
```

**Программа и база** (в новой версии была миграция). Сначала откатите базу до версии, которую ожидает старая программа (номер — в CHANGELOG старой версии), потом программу:

```bash
docker compose run --rm -e URM_ADMIN_USER=<адм.> -e URM_ADMIN_PASSWORD='<пароль>' urm python tools/migrate.py down 2
git checkout v2.1.0 && docker compose up -d
```

> Откат миграции может удалить то, что она создала. Например, откат 001 удаляет таблицу пользователей. Перед откатом базы сохраните её:
> ```bash
> pg_dump -h <хост> -p <порт> -U <администратор> -d URM -n urm2_app -f urm2_app_$(date +%F).sql
> ```

**Только данные.** Если снимок получился неудачным, предыдущий хранится рядом. Достаточно пересобрать текущий:

```bash
docker compose exec urm python tools/build_snapshot.py --force
```

Витрины `urm2` откатывает только Digital Direction: платформа их не меняет.

## Выпуск новой версии (для разработчика)

1. Работа ведётся в отдельной ветке, в `main` попадает через pull request. GitHub Actions на каждое изменение запускает проверку стиля, тесты (в том числе с настоящим PostgreSQL) и сборку образа.
2. Перед выпуском:
   - в `CHANGELOG.md` записать, что изменилось, и есть ли новые миграции;
   - увеличить номер в `VERSION` и `pyproject.toml`: исправление `2.1.1`, новая возможность `2.2.0`;
   - `git tag v2.2.0 && git push --tags`.
3. На тег GitHub соберёт образ и опубликует его в `ghcr.io/<организация>/<репозиторий>:2.2.0`. Тогда на сервере можно не собирать образ, а скачать готовый: в `docker-compose.yml` указать `image: ghcr.io/…:${URM_VERSION}` и убрать блок `build`.

## Резервные копии

| Что | Нужно ли копировать | Как |
| --- | --- | --- |
| Пользователи (`urm2_app`) | да, ежедневно вместе с базой | входит в обычный бэкап базы `URM` или `pg_dump -n urm2_app` |
| Маппинг (`urm2.*_mapping`) | да | бэкап базы `URM` (зона DD) |
| `.env` | да, в защищённом месте | вручную, не в git |
| Снимок (`urm-snapshots`) | нет | собирается заново за минуту |
| Код | нет | в git |
