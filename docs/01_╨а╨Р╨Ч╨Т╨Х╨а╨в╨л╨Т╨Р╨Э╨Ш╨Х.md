# 01. Развёртывание

Здесь описано, как поставить платформу на сервер так, чтобы она работала сама: подключалась к базе, обновляла данные после ночного расчёта и пускала пользователей по логину и паролю.

Время: около 30 минут. Понадобятся доступ к серверу с Docker и учётная запись администратора PostgreSQL (или владельца базы `URM`).

---

## Шаг 1. Сервер

Достаточно любого Linux-сервера, который видит базу `pg.data.ddirection.kz:55432`.

| Что | Сколько |
| --- | --- |
| Процессор | 2 ядра |
| Память | 4 ГБ |
| Диск | 2 ГБ под образ и снимки |
| Программы | Docker и Docker Compose (`docker compose version` должен отвечать) |

Проверить, что сервер видит базу:

```bash
nc -zv pg.data.ddirection.kz 55432      # должно быть «succeeded» / «open»
```

## Шаг 2. Код

```bash
git clone <адрес репозитория> urm
cd urm
cp .env.example .env
```

## Шаг 3. Файл настроек `.env`

Откройте `.env` в любом редакторе. Обязательно заполнить:

| Строка | Что вписать |
| --- | --- |
| `PGHOST`, `PGPORT`, `PGDATABASE` | адрес базы (уже стоит рабочий) |
| `URM_RO_USER`, `URM_RO_PASSWORD` | логин и пароль на чтение (`urm_app_ro` или `URM`) |
| `URM_RW_USER`, `URM_RW_PASSWORD` | логин и пароль на запись (`urm_app_rw` или `URM`) |
| `URM_NO_AUTH` | `0` — вход по логину и паролю (для пользователей) |

Остальные строки можно не трогать, в файле у каждой есть пояснение. Отдельно настраиваются надписи и подсказки в интерфейсе — см. [02 Администрирование](02_АДМИНИСТРИРОВАНИЕ.md#надписи-и-подсказки).

> `.env` содержит пароли. Он не попадает в git (указан в `.gitignore`), и пересылать его по почте нельзя.

## Шаг 4. База: учётные записи и таблица пользователей

Витрины `urm2` платформа не меняет. Нужно только создать её собственную маленькую схему `urm2_app` с пользователями.

### 4.1. Учётные записи PostgreSQL для платформы (рекомендуется)

Платформе лучше выдать две отдельные учётные записи, а не общий логин `URM` с полными правами:

- `urm_app_ro` — только чтение;
- `urm_app_rw` — запись только в шесть таблиц маппинга и в таблицу пользователей.

Администратор PostgreSQL выполняет:

```bash
psql -h pg.data.ddirection.kz -p 55432 -d URM -U <администратор> \
     -v ro_password='<пароль1>' -v rw_password='<пароль2>' \
     -f sql/migrations/000_db_roles.sql
```

Если решили работать под одним логином `URM`, этот шаг пропустите, а в `.env` укажите `URM` и для чтения, и для записи.

### 4.2. Таблица пользователей

```bash
docker compose run --rm -e URM_ADMIN_USER=<администратор> -e URM_ADMIN_PASSWORD='<пароль>' \
  urm python tools/migrate.py up
```

Нужна учётная запись с правом создавать схему в базе `URM` — администратор PostgreSQL или владелец базы. Если такими правами обладает логин из `URM_RW_USER`, части `-e …` можно не писать.

Ответ должен быть `001 применена`, `002 применена`. Повторный запуск ничего не ломает, он просто напишет «Новых миграций нет».

> Команды `docker compose run …` и `docker compose exec …` сами соберут образ при первом вызове. Без Docker то же самое делается командой `python tools/migrate.py up`.

## Шаг 5. Первый администратор

```bash
docker compose run --rm urm python tools/users.py add admin "Администратор УРМ" admin
```

Команда спросит пароль: только латинские буквы, цифры и знаки, без пробелов. Остальных пользователей администратор потом заведёт сам на странице «12 Пользователи».

## Шаг 6. Запуск

```bash
docker compose up -d --build
docker compose exec urm python tools/doctor.py
```

`doctor.py` проверяет всё по порядку: подключение, права, пользователей и снимок. В конце должно быть **«Итог: всё в порядке»**. Если нет, в строке с ✗ написано, что сделать.

Первый запуск занимает около минуты: платформа копирует витрины в снимок. Дальше она стартует за секунды.

## Шаг 7. Доступ для пользователей (HTTPS)

По умолчанию платформа слушает только сам сервер (`127.0.0.1:8501`). Пользователям её открывают через обычный веб-сервер с HTTPS. Пример для nginx:

```nginx
server {
    listen 443 ssl;
    server_name urm.kdlolymp.kz;                 # своё имя
    ssl_certificate     /etc/ssl/urm.crt;
    ssl_certificate_key /etc/ssl/urm.key;

    location / {
        proxy_pass http://127.0.0.1:8501;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;  # обязательно: Streamlit работает через WebSocket
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400;
    }
}
```

Если отдельного веб-сервера нет и платформа нужна только во внутренней сети, в `.env` можно добавить `URM_BIND=0.0.0.0`. Тогда она будет доступна на `http://<сервер>:8501` без HTTPS. В интернет её так открывать нельзя.

## Как это работает дальше само

- **Каждую ночь** Digital Direction публикует новые витрины. При первом обращении после этого платформа замечает публикацию и в фоне собирает новый снимок (около 30 с). Пока он собирается, все работают на предыдущем, без перерыва.
- **После перезагрузки сервера** контейнер поднимается сам (`restart: unless-stopped`), а снимок остаётся в томе `urm-snapshots`.
- **Временные файлы** платформа убирает сама: хранятся последние 2 снимка, брошенные недособранные удаляются через час, файлы Excel живут только во время скачивания. Подробнее — в [03 Архитектура](03_АРХИТЕКТУРА.md#файлы-и-временные-данные).
- **Журнал** пишется в стандартный вывод контейнера (`docker compose logs -f urm`) с ротацией 5 × 10 МБ. Входы, выходы и изменения пользователей отмечены словом `AUDIT`.

## Если что-то не так

| Признак | Что сделать |
| --- | --- |
| Страница не открывается | `docker compose ps`: контейнер должен быть `healthy`. Если нет — `docker compose logs --tail 100 urm` |
| «Данные недоступны…» на странице | `docker compose exec urm python tools/doctor.py`: обычно неверный пароль или сеть до базы |
| «Таблица учётных записей недоступна» | не выполнен шаг 4.2 |
| Никто не может войти | `docker compose exec urm python tools/users.py list`. Если администратора нет — шаг 5 |
| Через nginx страница «висит» на загрузке | в настройке nginx нет строк `Upgrade` / `Connection` (WebSocket) |
| Данные вчерашние | снимок собирается в фоне, подождите минуту. Принудительно: `docker compose exec urm python tools/build_snapshot.py --force` |
