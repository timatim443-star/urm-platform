# 02. Администрирование

## Роли

| Роль | Код | Видит данные | Страницы | Маппинг | Пользователи |
| --- | --- | --- | --- | --- | --- |
| Город | `city` | только своих городов (одного или нескольких) | 00–09 | — | — |
| Все города | `network` | всех городов | 00–09 | — | — |
| Администратор | `admin` | всех городов | 00–12 | просмотр и правка | заводит и меняет |

Одна лаборатория — один город. Пользователь роли «Город» не получает строк чужих городов вообще: ограничение срабатывает до фильтров, и подставить чужой город нельзя. Сетевые таблицы качества данных (покрытие маппинга, конфликты, воронка) не делятся по городам, поэтому этой роли они не показываются.

### Как изменить права роли

Права всех ролей описаны в одном файле: `urm/roles.py`. Например:

- чтобы дать роли «Все города» правку маппинга, у `network` поставьте `"mapping_edit": True` и добавьте `"mapping"` в её `pages`;
- чтобы скрыть страницу у роли, уберите её код из `pages`.

После правки перезапустите: `docker compose up -d --build`. Сами пользователи и их роли хранятся в базе, а `roles.py` определяет, что разрешено каждой роли.

## Пользователи

### В интерфейсе (обычный способ)

Администратор открывает **«12 Пользователи»**. Там три вкладки:

- **Добавить** — логин (латиница в нижнем регистре), имя, роль, города для роли «Город», пароль;
- **Изменить** — имя, роль, города, флаг «Активен». Снятый флаг запрещает вход, причём уже вошедший пользователь будет выведен в течение 5 минут;
- **Сменить пароль** — новый пароль для любого пользователя.

Удаления нет: пользователя выключают, история остаётся. Выключить или понизить последнего администратора нельзя, как и себя самого.

Администратор может сменить свой пароль в меню профиля справа сверху. У общих учёток («Город», «Все города») этой кнопки нет: пароль меняет администратор. Там же кнопка «Выйти».

### Из командной строки (первый администратор, восстановление доступа)

```bash
docker compose exec urm python tools/users.py list
docker compose exec urm python tools/users.py add ivanov "Иванов А.С." network
docker compose exec urm python tools/users.py add kim "Ким А." city karaganda,astana
docker compose exec urm python tools/users.py passwd ivanov
docker compose exec urm python tools/users.py set kim network
docker compose exec urm python tools/users.py disable kim
```

Ключи городов показывает `docker compose exec urm python tools/list_labs.py`.

### Правила входа

- **пароль** — любой длины, но только латинские буквы, цифры и знаки (`!@#…`), без пробелов и кириллицы. В базе хранится только хэш (pbkdf2-sha256), сам пароль не хранится нигде. Если пароль набран в русской раскладке, форма входа подскажет;
- **блокировки после неверных паролей нет**;
- **сессия сохраняется**: после входа браузер помнит пользователя — обновление страницы (F5), новая вкладка и даже перезапуск сервера не требуют входить заново. Вход действует `URM_SESSION_MINUTES` минут с момента входа (по умолчанию 240 = 4 часа), потом нужно войти снова. «Выйти» завершает сессию только на этом устройстве;
- **одна учётка — много людей**: под учёткой роли «Город» или «Все города» могут одновременно работать сколько угодно человек, у каждого свои фильтры. Поэтому свой пароль эти роли не меняют — его меняет администратор на «12 Пользователи»;
- **администратор — только с одного устройства**: новый вход под той же учёткой закрывает прежний, на старом устройстве появится «вошли с другого устройства». Настраивается флагом `single_session` у роли в `urm/roles.py`;
- выключенный пользователь теряет доступ сразу при обновлении страницы и не позже чем через 5 минут в открытой вкладке;
- сессии хранятся в файле `_sessions.json` в папке снимков (`URM_SNAPSHOT_DIR`, том `urm-snapshots`); в файле только хэши токенов. Удалить файл и перезапустить сервер — выйдут все;
- входы, выходы, неудачные попытки и изменения пользователей пишутся в журнал с меткой `AUDIT`:
  ```bash
  docker compose logs urm | grep AUDIT
  ```

## Надписи и подсказки

Все надписи интерфейса собраны в `urm/notices.py`. Они делятся на четыре вида:

| Вид | Что это | Пример |
| --- | --- | --- |
| `test` | метка тестового режима в блоке учётной записи | «тестовый режим» |
| `tech` | техническая информация | «срез: готовый пакет, 0.24 с» в подвале, длительность сборки снимка |
| `notice` | пояснения к цифрам | «Важно: «Расчетная дельта*» — аналитическое приближение…» |
| `hint` | всплывающие подсказки «?» у полей | «Список прокручивается и сужается по мере ввода» |

Что показывать, задаётся строкой в `.env`:

```bash
URM_UI_SHOW=notice,hint      # по умолчанию для пользователей: без технической информации
URM_UI_SHOW=hint             # убрать и пояснения на страницах
URM_UI_SHOW=                 # убрать всё
URM_UI_HIDE=delta_warning    # убрать отдельные надписи по коду (коды — в urm/notices.py)
```

Метку «тестовый режим» отключить нельзя. Она исчезает сама, когда в `.env` стоит `URM_NO_AUTH=0`: так тестовый режим не останется на рабочем сервере незамеченным.

После изменения `.env` выполните `docker compose up -d`.

## Маппинг

Страница «11 Маппинг» видна только администратору. Правки сохраняются сразу в базу. Если с момента открытия строку изменил кто-то другой, сохранение откажет и попросит перечитать. После правки база ставит флаг `reference_changed`, и следующий ночной расчёт Digital Direction учтёт изменения.

**До ночного расчёта отчёты показывают старое сопоставление.** Это нормально, на странице висит соответствующее предупреждение.

Перед массовыми правками сохраните выгрузку справочника. Истории версий в базе нет (см. руководство аналитика URM2, раздел о справочниках).

## Пороги аномалий

Пороги («критично — использовано ≤ 20 %», «внимание — ≤ 50 %» и т. д.) заданы в `urm/report_core.py`, класс `AnalyticsConfig`. Это копия генератора отчётов: менять пороги там можно, а остальной код этого файла лучше не трогать (см. [03](03_АРХИТЕКТУРА.md)).
